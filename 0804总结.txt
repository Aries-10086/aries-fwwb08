四、产品体验未来优化建议
------------------------
1. 演示叙事统一
   - 开场 30 秒讲清三角色与「正式考试」故事；管理端用正式考 + 开考说明录一段。
   - NL 查询旁贴必中问句卡片（与要求版 ①～⑤ + 同义说法一致）。

2. 党员手机主路径
   - 首页保持「任务 + 推荐理由 + 搜索」；测验入口突出正式考标签；交卷后引导错题讲解 / AI 报告。
   - AI 助手失败时横幅明确「主流程不受影响」，避免评委以为系统挂了。

3. 书记催办路径
   - 看板「未完成任务」+ 成绩「未参与」两跳即到人员详情；答辩时只走手机端即可。

4. 管理端「三分钟发测」
   - 内容页快捷派任务 → 组卷规则抽题凑满约 100 分 → 发正式考；录屏控制在 3 步内。


五、AI / 工程未来优化建议
------------------------
1. 降级策略对外可讲清
   - 超时 → 离线评语；无密钥 → 讲解/问答不可用但学习测验可用；无 Milvus → 轻量模式。
   - 审计页现场打开一条 `ai.timeout` / 成功调用，回应「可审计」。

2. 知识库
   - 轻量模式为默认答辩配置；完整 RAG 作为加分项，勿做成硬依赖。
   - 讲解面板始终展示「正确答案（题库只读）」，强调 AI 不改答案。

3. 工程卫生
   - 定期 `npm run check`；大包继续观察 chunk；演示前 `demo:all` 冷启动验收一次。
   - 本地未提交改动与远程 `08-miniprogram` 等保持同步习惯（stash → pull → pop）。


六、建议演示脚本（约 6 分钟）

5:20–6:00  收束：可解释推荐 / 离线降级 / 轻量知识库；留 Q&A
