三、产品体验优化建议
--------------------
1. 党员端信息架构
   - 现状：桌面顶栏导航，竖屏下拥挤、主流程分散。
   - 建议：手机壳布局（底栏：学习 / 测验 / 错题本 / 报告 / 我的）；首页只保留「任务进度 + 推荐 + 搜索」三块。

2. 正式考试体验
   - 现状：统一叫「测验」，演示时难讲清「正式考」故事线。
   - 建议：exam 增加 type=formal|quiz；正式考默认 maxAttempts=1、开考须勾选说明；列表用不同标签区分。

3. 任务与学习闭环 [已完成]
   - 任务卡片：「继续学习」直达下一篇未学内容；全部完成后引导「去测验 / 看报告」

4. 书记端定位 [已完成]
   - 支部看板增加「薄弱知识点」「错题 Top」卡片（按本支部错题汇总），并快捷入口到成绩明细 / AI 报告
   - 书记导航以看数据为主：支部看板、成绩、学习、测验、错题本、报告（已去掉任务发布）

5. 管理端操作路径
   - 题库→组卷→发测验→派任务链路较长。
   - 建议：看板或内容页增加「快捷：新建测验 / 派任务」入口；组卷页显示「总分校验」（应≈100）。


四、AI 能力优化建议
------------------
1. NL 查询做成「模板优先、LLM 兜底」
   - 先用正则/关键词命中 5～8 条固定问法（时间槽 + 组织槽 + 指标槽），保证演示必中。
   - 未命中再走 LLM 抽参；抽参失败返回「可点问法」列表，避免空白错误页。

2. 推荐可解释
   - 每条推荐附：来源（错题类别 / 任务必学 / 冷启动热门）+ 一句理由。
   - 无学习记录时：公共内容 + 本支部当期任务内容，文案写清「新用户默认推荐」。

3. 报告对比与行动
   - 报告增加：个人分 vs 支部均分 / 支部最高分。
   - 「建议」项绑定 contentId，点击直达学习页；无 LLM 时用固定三段式模板（优点/短板/行动）。

4. 工程降级
   - 服务端 AbortSignal / 超时 8～10s；超时写 ai_logs，前端展示「已使用离线评语」。
   - 管理端增加「AI 调用日志 / 操作审计」只读页，方便答辩答「可审计」。


五、技术与工程优化建议
----------------------
1. 前端包体
   - 构建提示 chunk >500KB；建议按路由 code-split（管理端 / 党员端 / 图表库分开）。

2. 题库与组卷
   - 已有 100+ 题，组卷仍偏手工。
   - 建议：按分类/题型「一键抽 N 题」；AI 出卷可先做规则版再接 NL。

3. 数据与演示稳定性
   - 建议提供 `npm run seed:demo`：重置演示任务进度、一份标准测验成绩，保证录屏数据好看。
   - 演示账号密码已有文档；答辩前确认 Docker Postgres 一次拉起脚本写进 README「三分钟启动」。

4. 权限边界
   - 书记不可进任务发布已对齐；继续复核 `/admin/*` 路由是否均有 role 守卫，防止直链进入。

5. 搜索与列表
   - 内容/人员已支持本地搜索；组织层级较深时可加「全局搜组织/人员」入口，减少层层点选。


六、交付材料建议（答辩前必备）
------------------------------
1. 演示视频脚本（约 6 分钟）
   - 管理员：发内容 → 组卷发测 → 派任务 → 看板筛选下钻 → NL 问 2 句
   - 书记：支部看板 + 成绩
   - 党员：学任务 → 测验 → 错题重练 → AI 报告

2. 一页纸说明
   - 架构（React + Express + PostgreSQL + LLM）
   - AI 三件套：推荐 / NL / 报告 的输入输出与降级策略
   - 冷启动策略三句话

3. 必中问句卡片（贴屏幕旁）
   - 与 `0803要求版.txt` 中 ①～⑤ 对齐，并各备 1 个同义说法

--------------
功能骨架已够讲「学习—测验—统计—AI」闭环；要冲刺验收，应优先补「手机观感、正式考试故事、NL 必中、推荐/报告可解释」，并把演示视频与一页纸材料当作同等重要的交付物，而不是事后补丁。
