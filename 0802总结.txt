0802 系统缺陷与优化总结
========================
整理日期：2026-07-22
项目：基于 AI 的数智党校学习系统（08）

一、功能缺陷 / Bug / 未完成
----------------------------
1. 测验无倒计时与服务端时限校验
   - 前端只展示考试时长，无倒计时；后端提交不校验用时，可无限答题。

2. 交卷未校验测验状态与支部归属
   - 草稿/已关闭测验、跨支部用户仍可能提交成功。

3. 测验可无限重考
   - 无作答次数限制；历史成绩对比不足。

4. 「标记完成」状态刷新后丢失
   - 未从 learning_records 回读已完成态，刷新页面按钮回到「标记完成」。

5. 学习时长统计易虚高
   - 离开页面时清理逻辑易重复写入未完成记录；记录只增不改，口径混乱。

6. 无学习进度查询接口
   - 仅有写入记录，移动端难以展示「已学/未学」进度。

7. 学习任务缺少编辑/删除
   - 后端基本只能创建；截止时间等字段前端基本未用。

8. 题库 / 试卷 / 测验缺少删除能力
   - 题目无法下架；试卷、测验清理不便。

9. 视频非真正播放
   - 仅把 URL 放正文首行外链，无内嵌播放器；演示数据多为占位链接。

10. 党员端缺少内容搜索
    - 赛题期望浏览与搜索；后端虽有 q 参数，前端首页无搜索入口。

11. 支部书记可建任务但无对应 UI
    - API 允许 secretary 发任务，但管理端任务页仅管理员可进。

12. 改密接口无前端入口
    - 有 change-password API，登录/个人中心无改密页面。

13. 注册支部选择可静默回落
    - 未选支部时落到默认支部，可能进错组织。

14. 部分页面标题字色几乎不可见
    - 多页残留深色主题字色（如 text-zinc-50），白底上可读性差。


二、安全问题（优先处理）—— 2026-07-22 已加固
--------------------------------------------
1. 【致命】伪鉴权可提权 —— 已修复
   - 现改为 HMAC 签名 access token（Authorization: Bearer）
   - 角色一律从数据库读取，忽略客户端 x-role / x-user-id

2. 部分敏感列表接口缺少登录校验 —— 已修复
   - users 仅管理员；org-units / contents / tasks / exams 需登录

3. 未登录时内容/任务过滤不严 —— 已修复
   - 未登录直接 401；非管理员任务强制按本支部过滤

4. AI 推荐/报告可指定任意 userId —— 已修复
   - 强制使用当前登录用户，忽略 body.userId

5. 上传文件目录匿名可访问 —— 已修复
   - 取消公开 /uploads 静态目录
   - 改为 /api/files/:name，需登录且校验内容访问权

6. 开放注册无审核、登录无防爆破 —— 已部分加固
   - 登录/注册增加 IP 限流
   - 可用环境变量 ALLOW_OPEN_REGISTER=0 关闭开放注册
   - 注册必须选择支部（禁止静默落到默认支部）

7. 演示弱口令与导入默认弱密码 —— 已部分加固
   - 导入禁止缺省 123456，密码必填且 ≥6 位
   - 演示账号仍保留便于评测（见 测试账号密码.txt）
   - 生产建议设置 AUTH_SECRET 并修改演示密码

8. CORS 全开、上传类型校验偏弱 —— 已加固
   - CORS 默认仅允许 localhost:5173
   - 去掉 zip；补充 MIME 校验


三、体验 / 产品缺口
--------------------
1. 「双端」实际是一套 Web 响应式，非独立移动端/小程序壳。
2. 书记有「支部成绩」，但缺少完整支部数据看板入口（时长、完成率等）。
3. 任务列表看不到完成勾选/进度条。
4. 考试结果弱：错题回顾、历史成绩列表不足。
5. AI 自然语言查询对「今年」等时间语义解析不足。
6. 无个人中心（资料、改密、我的成绩、学习时长汇总）。
7. 党员综合评价「个人排名」不足，目前更偏支部均分排行。


四、技术债 / 性能 / 架构优化
----------------------------
1. 鉴权改为服务端会话或 JWT，角色从数据库读取，禁止客户端自报角色。
2. 组织统计、成员成绩存在 N+1 查询，数据量大时会变慢，宜批量聚合。
3. 学习记录改为按 (user_id, content_id) upsert，统一完成率与时长口径。
4. SQLite 缺外键约束，删组织/用户易留脏数据。
5. LLM 无配置时走 mock 文案，答辩前需接通真实国内大模型并写清说明。
6. shared/types 与实际字段不同步（如 username、attachments）。
7. 多处吞异常、服务端错误日志不足。
8. Vite 代理日志过吵，干扰开发排查。
9. SQLite 单文件适合演示，不适合高并发正式部署。

六、建议优先修复顺序
--------------------
1. 鉴权与未鉴权接口（安全）
2. 完成态回显、学习时长统计、测验提交校验（正确性）
3. 统一浅色主题字色（演示观感）
4. 内容搜索、考试计时、任务改删、真实 LLM 接入（完整度）
5. 个人中心、错题回顾、党员排名、上传鉴权（增强项）
